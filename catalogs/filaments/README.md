# Filament catalog

STL Quest includes a generated filament catalog so a workspace adds the filaments it buys by product and colour instead of typing names. Self-hosted installations read it locally and do not contact third-party services while the app is running.

The catalog is a slim copy of [SpoolmanDB](https://github.com/Donkie/SpoolmanDB), the community filament database behind Spoolman, pinned to the revision in `sources.json`. SpoolmanDB lists each product once per spool size and diameter under a name template such as `Matte {color_name}`; the generator folds those into one product per line and material ("Matte PLA", or just "ePLA+HS" when the line already names the material) and keeps its material, density, and every colour's name and hex value. Spool sizes, diameters, and temperatures are left out because pricing does not use them. A manufacturer sometimes lists several products under one template, such as Bambu Lab's basic, marble, and gradient `{color_name}` PLA; SpoolmanDB's `pattern`, `translucent`, `glow`, and `multi_color_direction` attributes then prefix the name ("Marble PLA", "Translucent PETG", "Gradient PLA", "Dual Color Silk PLA"), and the product with none of them keeps the plain name and ID. An entry holding a single colour stays with its product line, since an attribute there marks that colour rather than a separate product, such as Protopasta's translucent Natural Basic PLA. Products told apart only by density, such as Bambu Lab's ASA and ASA Aero, stay merged.

SpoolmanDB carries no manufacturer colour codes, so Bambu Lab's come from [Bambu Studio](https://github.com/bambulab/BambuStudio)'s `filaments_color_codes.json`, the table behind its AMS colours, pinned in `sources.json` like SpoolmanDB. These are the codes its store prints beside each colour ("Gray (10103)"), in every language, so a German or French order email matches by code rather than by its translated name. A code is recorded on a colour only when Bambu Studio's product, English colour name, and hex value all agree with SpoolmanDB's, and a colour two codes claim gets neither: SpoolmanDB folds some products Bambu Lab sells apart, such as Silk and Silk+ PLA, into one. Colours Bambu Studio names differently, such as its "Glow Orange" for SpoolmanDB's Glow PLA "Orange", have no code and still match by name. The checker requires every code to be five digits, as order emails print them, and unique within its brand.

`overrides.json` patches a generated product's name by ID, where SpoolmanDB's name differs from the one the manufacturer sells it under, such as Bambu Lab's PLA Basic. A patch never changes the ID, since workspaces keep the ID of the product they chose.

Prices are deliberately excluded: SpoolmanDB carries none, and they vary by seller, region, spool size, and purchase date. Users choose a product and colour, then save their own price per kilogram.

Run `pnpm catalog:sync` to regenerate the catalog from the recorded revision, `pnpm catalog:update` to move to SpoolmanDB's current `main`, and `pnpm catalog:check` to validate the committed catalog without using the network.
